Tunning Process

This page documents the control tunning and integration process executed during simulation-to-hardware transition. It records what was tuned, why each tuning action was required, outcomes observed, and issues encountered.

Tunning Process

The tunning workflow was executed iteratively across kinematic validation, sign-convention correction, startup calibration gating, and controller handover tests. The main objective was to make real hardware behavior consistent with model assumptions before aggressive balancing was enabled.

Phase What was tuned Outcome Issue encountered
FK/command direction check Incremental command mapping for \(\mathbf{G}\)-point motion (\(20\,\mathrm{mm}\) steps). Confirmed commanded \(\pm\) increments produced expected endpoint direction trends. Early sign ambiguity between controller channels and hardware direction.
Sign-convention alignment Pitch and pitch-rate mapping between model and firmware runtime variables. LQR columns for \(\phi,\dot{\phi}\) correctly sign-flipped for firmware convention. Model used forward tilt \(+\phi\), firmware used forward tilt as negative pitch.
Startup calibration gating Readiness sequence for IMU bias, encoder validity, actuator polarity, and safe mode handover. Fixed startup path: calibration \(\rightarrow\) leg-length hold \(\rightarrow\) LQR. Needed explicit fail gates to block control if any readiness flag was invalid.
Transmission conversion Gearbox + chain ratio conversion from motor encoder variation to \(\phi_1,\phi_2\) change. Quantified mapping used for controller-side joint interpretation. Mechanical advantage ratio had to be applied in correct driver/driven direction.

Live-expression and runtime debug reference: tuning_live_expression_check.c

Leg Length PD Tunning + Feedforward

Leg-length control was used as a hold/support loop during bring-up to stabilize posture while validating sign, kinematics, and state mapping. This loop was intentionally kept conservative and not fully tuned at this stage.

Feedforward support force was initialized from equivalent mass distribution: \[ F_{\mathrm{ff,ground}} = \frac{(M+m_p+m_w)g}{2\cos\theta_{\mathrm{nom}}}, \qquad F_{\mathrm{ff,air}} = \frac{(m_p+m_w)g}{2\cos\theta_{\mathrm{nom}}}. \] With \(M=8.7\), \(m_p=4.32716\), \(m_w=1.58832\), \(g=9.81\), and \(\theta_{\mathrm{nom}}=0\): \[ F_{\mathrm{ff,ground}} \approx 71.69\ \mathrm{N/leg}, \qquad F_{\mathrm{ff,air}} \approx 29.01\ \mathrm{N/leg}. \]

Item Tunning action Reason Observed result
PD proportional gain \(K_p\) Raised until leg-length tracking was responsive without immediate oscillation. Needed sufficient stiffness for hold posture. Improved hold stiffness but high values increased vibration tendency.
PD derivative gain \(K_d\) Increased to damp transient bounce after disturbances. Reduce overshoot and oscillatory response. Reduced ringing; excessive \(K_d\) amplified measurement noise.
Feedforward force Initialized from mass-based formula, then adjusted by test behavior. Reduce steady error burden on PD loop. Lower steady correction demand and smoother hold transition.

Reference codes: leg_length_pd_feedforward_tuning.c, build_reduced_model_note.c

Threshhold Tunning for off the ground detection

Off-ground detection threshold tunning was used to switch between ground-support and air-support assumptions, avoiding incorrect force allocation when contact state changes.

Signal Threshold logic Why tuned Issue encountered
Estimated support force / normal-force proxy Below threshold for \(N\) consecutive cycles \(\rightarrow\) off-ground. Prevent false mode switching from transient noise. Too low threshold caused delayed mode update.
Pitch-rate / acceleration disturbance window Hold state for a debounce window before switching state. Avoid chatter when crossing contact boundary. Too short debounce caused repeated toggling.
Hysteresis band Different enter/exit thresholds for ground-contact state. Improve stability under vibration. Narrow hysteresis produced unstable contact flag.

Reference code: off_ground_threshold_tuning.c
