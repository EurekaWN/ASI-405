7. Firmware System Architecture

This section documents the runtime firmware architecture from sensing to estimation, control allocation, actuator interfacing, and output safety limiting. The structure is written as implementation-oriented documentation to support tuning, debugging, and future maintenance.

System Structure

The firmware is organized as a deterministic pipeline: \[ \text{Acquire} \rightarrow \text{Estimate} \rightarrow \text{Control} \rightarrow \text{Map/Limit} \rightarrow \text{Actuate}. \] The design objective is to guarantee signal validity and sign consistency before control commands are issued.

Layer Function Typical outputs
Acquisition IMU, encoder, and motor telemetry ingestion with freshness checks. \(pitch,\ \dot{pitch},\ rpm,\ encoder\ angle\)
Estimation Bias-corrected attitude and translational state reconstruction. \(x,\dot{x},\theta,\dot{\theta},\phi,\dot{\phi}\)
Control LQR/VMC/PD calculations in model-consistent coordinates. \(u=[T,\ T_p]^T\)
Mapping + Safety Driver command mapping, saturation, rate limiting, interlocks. Safe actuator command packets

Reference code: firmware_system_structure.c

IMU Processing

IMU processing includes startup bias capture, runtime bias compensation, filtering, and sign-convention alignment. A key integration constraint from the prior process is that firmware pitch sign is opposite to model \(+\phi\), therefore a mapping step is explicitly applied before state-vector assembly.

  1. Read raw gyroscope and accelerometer channels.
  2. Subtract startup-estimated bias terms.
  3. Apply low-pass/complementary filtering.
  4. Map to model sign convention for controller input channels.

Reference codes: imu_processing_pipeline.c, sign_convention_alignment_check.c

Kalman Filter for Body speed/position Estimation

Translational state estimation is implemented as a linear Kalman filter using discrete prediction-correction form: \[ \mathbf{x}_{k|k-1}=A_d\mathbf{x}_{k-1|k-1}+B_d\mathbf{u}_{k-1},\qquad P_{k|k-1}=A_dP_{k-1|k-1}A_d^T+Q \] \[ K_k=P_{k|k-1}H^T(HP_{k|k-1}H^T+R)^{-1},\qquad \mathbf{x}_{k|k}=\mathbf{x}_{k|k-1}+K_k(\mathbf{z}_k-H\mathbf{x}_{k|k-1}). \]

The filter is tuned to balance responsiveness and noise immunity. In this project workflow, the filter also serves as a stabilizing bridge between noisy wheel telemetry and control-state requirements.

Reference code: kalman_body_state_estimator.c

HT8108 joint motor control interface

The HT8108 interface performs command packing, communication transmission, and telemetry monitoring for joint channels. Commands are converted from physical units into protocol-specific packed integers with strict min/max clamping.

Practical issues encountered during integration include sign mismatch, parameter-limit clipping, and communication timeout handling. Therefore, the interface includes both command validation and readback consistency checks before high-level control trust.

Reference codes: ht8108_interface_flow.c, actuator_readiness_gate.c

M3508 wheel motor control interface

The M3508 interface maps generalized wheel-channel commands to left/right motors and reconstructs wheel speed/position from encoder telemetry for estimation and feedback closure.

Because mirrored wheel installation can invert observed direction, per-channel sign correction is applied before computing: \[ \dot{x}_{fw}=\frac{v_L+v_R}{2}. \] This was necessary to prevent directional inversion in speed feedback loops.

Reference code: m3508_interface_flow.c

Torque command saturation and output limiting

Output limiting is implemented to ensure motor commands remain within electrical, thermal, and stability-safe envelopes. Hard magnitude clipping and optional slew-rate limits are applied before command transmission.

\[ u_i^{sat}=\mathrm{clip}(u_i,\,-u_{i,\max},\,u_{i,\max}), \qquad \dot{u}_i^{sat}=\mathrm{clip}\!\left(\frac{u_i(k)-u_i(k-1)}{T_s},-\dot{u}_{i,\max},\dot{u}_{i,\max}\right). \]

Over-tilt cut-off is treated as a higher-priority safety interlock: if \(|pitch|>pitch_{lim}\), torque output is forced to zero.

Reference codes: torque_saturation_output_limit.c, over_tilt_safety_cutoff.c
